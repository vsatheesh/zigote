# 005 Command-line tool

Status: Accepted. Binary: `zigote` (`src/main.zig`).

## Purpose

Summarize a FASTA file from the command line, for people who do not write Zig. It is built on `zigote.fasta` (spec 001) and has no parsing logic of its own. This is the 0.1 scope; FASTQ and gzip arrive with specs 002 and 003.

## Usage sketch

```sh
zigote stats genome.fa                    # statistics for a file
zigote stats --parse-only genome.fa       # record and residue counts only
gunzip -c genome.fa.gz | zigote stats     # standard input (FILE omitted or -)
zigote --help                             # or -h
zigote --version                          # or -v
```

## Requirements

| ID | Requirement |
|----|-------------|
| CL-R1 | Commands: `stats`, `--help`/`-h` and `--version`/`-v`. `--help` or `-h` after `stats` also prints help. No arguments, an unknown command, an unknown option, or an extra argument after `--help`/`--version` is a usage error. |
| CL-R2 | `stats` reads one input: a file path, or standard input when FILE is `-` or omitted. A second FILE is a usage error. `--parse-only` may come before or after FILE. |
| CL-R3 | `stats` writes to stdout, in this order, one `key: value` line each, with the value starting at column 16: `file`, `records`, `residues`, `longest`, `shortest`, `N50`, `GC%`, `N`, `lowercase`, `empty ids`. `file` is the path as given, or `-` for stdin. |
| CL-R4 | Definitions. `records`: number of records. `residues`: total `seq` bytes, after spaces, tabs and line terminators are removed (FA-R2, FA-R19). `longest`, `shortest`: longest and shortest `seq` lengths. `N50`: the largest length L such that records of length L or more hold at least half of all residues. `GC%`: 100 × (G + C) / (A + C + G + T), case-insensitive, counting only those four letters, two decimals. `N`: count of `N` and `n`. `lowercase`: count of bytes `a` to `z`, then their share of residues as a percentage with two decimals. `empty ids`: records whose `id` is empty (FA-R15). |
| CL-R5 | With zero records, `longest`, `shortest` and `N50` are omitted. When there are no A, C, G or T bytes, `GC%` is omitted. All other lines are always written. |
| CL-R6 | `stats --parse-only` writes only the `records` and `residues` lines, in the CL-R3 format. |
| CL-R7 | Errors go to stderr and nothing is written to stdout. A file that cannot be opened: `zigote: cannot open PATH: ERROR`. A parse or read error: `zigote: PATH: line N: ERROR`, where N is `parser.line` (FA-R10) and PATH is `-` for stdin. A usage error: `zigote: MESSAGE[: ARG]` followed by the help text. |
| CL-R8 | Exit codes: 0 on success (including `--help` and `--version`), 1 for an open, read or parse error, 2 for a usage error. |
| CL-R9 | `--version` prints `zigote VERSION`, where VERSION is `.version` in `build.zig.zon`. A release tag is `vVERSION`, or `vVERSION-SUFFIX` for a pre-release. |
| CL-R10 | Gzip input is not detected in 0.1. A gzip file is read as FASTA and fails with `MissingHeader` (exit 1). The help text shows the `gunzip -c` workaround. |

## Decisions

1. **A `stats` command, not a bare file argument** (CL-R1). Later formats and operations (FASTQ, validation) become new commands without changing what `zigote FILE` means.
2. **One input** (CL-R2). Several files raise questions with no obvious answer (one report or one per file, how errors in one file affect the rest). Shell loops cover the need for now.
3. **The text output may change before 1.0** (CL-R3). It is for people to read. Changes are listed in the release notes. A machine-readable format (TSV) is a later addition with its own requirement, rather than a promise made now.
4. **`--parse-only` is public** (CL-R6). The benchmarks use it to time the parser alone, and it is a quick way to count records.
5. **Exit codes 1 and 2** (CL-R8). Scripts can tell bad data (1) from a bad command line (2), the convention of `grep` and `diff`.
6. **Version from `build.zig.zon`** (CL-R9). One source of truth; the release workflow refuses a tag that does not match it.

## Release

- Targets: `x86_64-linux-musl`, `aarch64-linux-musl` (static), `x86_64-macos`, `aarch64-macos`, `x86_64-windows`.
- Built with `-Doptimize=ReleaseSafe`: safety checks stay on, so a bug stops with a clear panic instead of printing wrong numbers. On `bench/data/long.fa` it is about 15% slower than ReleaseFast (32.5 vs 28.1 ms for `--parse-only`, 97.8 vs 85.8 ms for full stats). Users who want maximum speed can build from source with ReleaseFast.
- Archives: `zigote-vVERSION-TARGET.tar.gz`, or `.zip` for Windows, each holding the binary, `LICENSE` and `README.md`, plus a `SHA256SUMS` file.
- Built by `.github/workflows/release.yml` when a `v*` tag is pushed. It runs the tests, checks the tag against CL-R9, cross-compiles, smoke-tests the Linux x86-64 binary, and creates the GitHub Release.
- macOS binaries are not signed or notarized. Gatekeeper blocks them until the quarantine flag is removed (`xattr -d com.apple.quarantine zigote`); the README says so.

## Test plan

- Unit tests in `src/main.zig`: argument parsing (CL-R1, CL-R2) through `parseArgs`, and the report (CL-R3 to CL-R5) through `Stats` with a fixed reader.
- End-to-end checks in `build.zig`, part of `zig build test`: run the built binary with stdin input and check stdout, stderr and the exit code for `stats`, `stats -`, `--parse-only`, `--version`, `--help`, a usage error, two inputs, a missing file and malformed input (CL-R1 to CL-R9).
- CL-R10 has no automated test; it follows from FA-R8.
- Release: a pre-release tag (`v0.1.0-rc1`) is pushed first and its archives are downloaded and run by hand on macOS.
